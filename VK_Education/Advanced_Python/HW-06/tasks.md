# ЗАДАНИЕ

Необходимо реализовать асинхронный CLI-агрегатор, который опрашивает набор виртуальных сервисов, обрабатывает сбои, ограничивает нагрузку и формирует детальный отчёт.

В рамках этого домашнего задания необходимо выполнить 4 шага:
1. Реализовать базовый асинхронный опрос с таймаутами.
2. Добавить механизм повторных попыток (Retry) с экспоненциальной задержкой.
3. Реализовать ограничение конкурентности через семафоры.
4. Создать CLI-интерфейс с выводом прогресса и генерацией JSON-отчёта.

---

## Требования к коду

* Необходимо использовать стандартную библиотеку.
* Код должен соответствовать PEP 8.
* Запрещено возвращать `None` при ошибке, необходимо выбрасывать указанные исключения.
* **Важно:** Таймаут не считается критической ошибкой. Исключение `TimeoutError` должно перехватываться внутри `check_services`, а не выбрасываться наружу.
* Допускается отсутствие строгих тайп хинтов, но их наличие приветствуется.

---

## Домашнее задание №6

### Шаг 1. Базовый асинхронный опрос с таймаутами
**Задача:** Реализовать конкурентный опрос сервисов с контролем времени выполнения.

1. Реализуйте функцию-симуляцию `simulate_service(name, delay)`, которая ожидает `delay` секунд и возвращает словарь с результатом.
2. Напишите асинхронную функцию `check_services(configs, timeout_per_service)`, запускающую опрос всех сервисов конкурентно.
3. Используйте `asyncio.timeout()` для контроля времени. При превышении таймаута сервис должен получать статус `timeout`.

**Важно:** Функция должна возвращать список результатов в порядке вызова.

### Шаг 2. Retry с экспоненциальной задержкой
**Задача:** Обернуть логику опроса в механизм повторных попыток для повышения отказоустойчивости.

1. При возникновении `TimeoutError` или `ConnectionError` повторите вызов до `max_retries=3` раз.
2. Реализуйте экспоненциальную задержку между попытками: `base_delay * (2 ** attempt_index)`.
3. Сохраняйте общее количество совершенных попыток в результате каждого сервиса.

**Важно:** Если после всех попыток сервис не ответил, верните статус `error`.

### Шаг 3. Ограничение конкурентности
**Задача:** Добавить контроль нагрузки на систему с помощью семафоров.

1. Используйте `asyncio.Semaphore` для ограничения количества одновременных запросов (по умолчанию до 2).
2. Убедитесь, что семафор применяется до выполнения retry-логики, чтобы лимит соблюдался даже при повторных попытках.
3. Сохраните всю предыдущую функциональность (таймауты, детализация).

### Шаг 4. CLI, прогресс и JSON-отчёт
**Задача:** Превратить скрипт в полноценную утилиту командной строки.

1. Используйте `argparse` для приёма параметров: `--timeout`, `--retries`, `--concurrency`, `--output`.
2. Реализуйте текстовый индикатор прогресса в консоли без использования внешних библиотек.
3. Сохраняйте итоговый отчёт в JSON-файл при указании соответствующего флага.

**Важно:** Программа должна возвращать exit code `1`, если хотя бы один сервис завершился с ошибкой или таймаутом после всех попыток.
