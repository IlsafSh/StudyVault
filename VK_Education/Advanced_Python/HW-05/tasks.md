# ЗАДАНИЕ

Необходимо создать конвейер ETL «Конкурентный конвейер», который работает эффективно как в стандартном Python, так и в Free-Threading (3.14+), автоматически выбирая стратегию параллелизма. 

Каждый этап формируется на основе предыдущего с использованием наследования классов. Ожидаемый MRO: `[RobustPipeline, AdaptivePipeline, SafePipeline, Pipeline]`.

В рамках этого домашнего задания необходимо выполнить 4 шага:
1. Реализовать базовую архитектуру конвейера.
2. Обеспечить потокобезопасность общего состояния.
3. Реализовать адаптацию под NoGIL (Graceful Degradation).
4. Добавить обработку ошибок и устойчивость системы.

---

## Требования к коду

* Необходимо использовать стандартную библиотеку.
* Код должен соответствовать PEP 8.
* Запрещено возвращать `None` при ошибке, необходимо выбрасывать указанные исключения.
* Допускается отсутствие строгих тайп хинтов, но их наличие приветствуется.

## Домашнее задание №5

### Шаг 1. Базовая архитектура конвейера
**Задача:** Реализовать конвейер-класс `Pipeline` из трех этапов, связанных очередями (`queue.Queue`).

1. **fetcher:** Генерирует задачу (имитация скачивания) и возвращает её в виде строки.
2. **processor:** Выполняет CPU-ёмкую операцию (хеширование строки в цикле на большое число итераций).
3. **storer:** Сохраняет результат в общий словарь `results`.
4. **worker:** Реализует метод `worker(task_id)` по паттерну «Шаблонный метод», последовательно вызывая этапы для одной задачи.
5. **run:** Принимает список задач и запускает конвейер через `concurrent.futures.ThreadPoolExecutor`.

**Важно:** Убедитесь, что пайплайн корректно останавливается по завершении всех задач.

### Шаг 2. Потокобезопасность общего состояния
**Задача:** В новом классе `SafePipeline` защитить запись в `self.results` для корректной работы в многопоточной среде (особенно в NoGIL).

1. Добавьте `threading.Lock` для защиты критической секции записи.
2. Используйте контекстный менеджер (`with lock:`).

**Важно:** Не блокируйте очередь или I/O-операции внутри блока `with`, минимизируйте время удержания блокировки.

### Шаг 3. Адаптация под NoGIL (Graceful Degradation)
**Задача:** Реализовать фабрику исполнителей `get_executor` в классе `AdaptivePipeline`, выбирающую тип пула в зависимости от среды.

1. Проверьте статус GIL через `sysconfig.get_config_var("Py_GIL_DISABLED")` и `sys._is_gil_enabled()`.
2. Если GIL отключен (Free-Threading): используйте `ThreadPoolExecutor`.
3. Если GIL включен: используйте `ProcessPoolExecutor` для этапа `processor`.
4. Выведите выбранную стратегию в лог при старте.

**Важно:** При использовании `ProcessPoolExecutor` замените `self.results` на `multiprocessing.Manager().dict()` для обеспечения общей памяти между процессами.

### Шаг 4. Обработка ошибок и устойчивость
**Задача:** Реализовать класс `RobustPipeline`, который продолжает работу при возникновении ошибок в отдельных задачах.

1. Оберните логику `worker` в блок `try/except`, логируйте ошибки без прерывания потока.
2. Убедитесь, что остальные задачи продолжают выполняться после сбоя.
3. В методе `run` обеспечьте ожидание завершения всех запущенных задач.
